# 要件定義書 — Studio Book Mobile

- 更新日：2026-11-17
- 対象：React Native / Expo クライアント
- 根拠：`app/`, `src/`, `tests/`, 既存README
- ステータス：実装準拠（バックエンドの全仕様の保証ではない）

## 1. 背景・目的

既存の Studio Book Web 版（.NET 10 / Next.js）の一般利用者向け機能を、iOS / Android のスマートフォンUIから利用できるようにする。Web とモバイルで ASP.NET Core Web API を共有し、サーバー上の業務ルール・予約価格・AI処理・決済確定を二重実装しない。

## 2. 対象利用者と権限

| 区分 | モバイルでの扱い | 備考 |
|---|---|---|
| 未ログイン利用者 | 一覧・詳細・AI検索など公開機能を利用 | 予約・予約履歴・レビュー投稿はログインが必要 |
| 一般会員 `GeneralUser` | ログイン、予約確認、決済画面への遷移、予約履歴、レビュー投稿、会員情報更新 | モバイルの主対象 |
| `Host` | ログイン拒否 | Web版の管理機能を使用 |
| `Admin` | ログイン拒否 | Web版の管理機能を使用 |
| `GeneralUser` と管理ロールの兼任 | ログイン拒否 | アプリの `isMobileGeneralUser` に準拠 |

**注意**：クライアントのロール判定は補助的な制御であり、API側でも本人の予約・会員・レビューへの認可が必要。

## 3. 機能要件

| ID | 機能 | 要求・実装範囲 | 対応画面 |
|---|---|---|---|
| FR-01 | スタジオ一覧検索 | キーワード、エリア、上限料金、並び順、ページング | `(tabs)/index` |
| FR-02 | スタジオ詳細 | 写真、説明、所在地、料金、定員、営業時間、評価 | `rooms/[id]/index` |
| FR-03 | AIスタジオ検索 | 最大200文字の自然文入力、条件解釈、推薦理由、空き状況、429案内 | `rooms/ai-search` |
| FR-04 | 空き状況カレンダー | 30分単位の日表示、週内日付選択、前日/翌日/今日、営業時間・予約済み・休館の色分け | `RoomCalendar` |
| FR-05 | 予約日時入力 | 日・時刻選択、過去・逆転時刻・既知の予約/休館との重複を検出 | `rooms/[id]/book` |
| FR-06 | 予約確認 | サーバーから空き状況・料金・税額・手数料・Checkout URL を取得 | `rooms/[id]/confirm` |
| FR-07 | 決済画面への遷移 | 許可したHTTPSのStripe Checkout/設定済み独自ホストに限り外部ブラウザで開く | `rooms/[id]/confirm` |
| FR-08 | 予約履歴 | 一般会員の予約状況・決済状況の表示、ページング、再取得 | `(tabs)/reservations` |
| FR-09 | 認証 | ログイン、保存済みJWTの復元、ログアウト、一般会員のロールチェック | `login`, `AuthProvider` |
| FR-10 | 会員情報 | 表示、再取得、プロフィール編集 | `(tabs)/account`, `profile-edit` |
| FR-11 | レビュー閲覧 | 評価・本文・ホスト返信（存在する場合） | `RoomReviews` |
| FR-12 | レビュー投稿 | 利用済み予約から投稿、評価1～5、本文、`canReview` / 投稿済み判定 | `rooms/[id]/reviews/new` |
| FR-13 | AIレビュー補助 | 既存APIで文章を整形し、利用者が確認・編集してから投稿 | `rooms/[id]/reviews/new` |
| FR-14 | パスワード表示切替 | ログイン時のパスワード表示/非表示 | `PasswordField` |

## 4. 対象外

- 一般会員による予約取消（**取消はホスト・管理者側が実施**。取消済み状態の参照は対象）
- `Host` / `Admin` のログイン・管理画面、スタジオ登録/編集、ホスト返信の投稿
- モバイル内での新規会員登録、パスワード再設定（Web版を利用）
- アプリ内でのStripeカード決済UI実装、クライアントでの決済成功確定
- バックエンドの予約・料金計算・AI推論処理の再実装
- E2Eテスト、ストア公開、Android実機動作保証（現段階）

## 5. 非機能要件・設計方針

| ID | 項目 | 内容・現在の実装方針 |
|---|---|---|
| NFR-01 | プラットフォーム | React Native + Expo Router によるiOS/Android共通コード。実機検証状況は別管理 |
| NFR-02 | 通信 | 本番APIはHTTPS。開発時の`localhost`/Androidエミュレータ`10.0.2.2`は例外的に許可 |
| NFR-03 | 認証情報 | JWTを`expo-secure-store`で保存。401時はトークン削除、403時は維持 |
| NFR-04 | 秘密情報 | AIキーやStripe秘密鍵をアプリへ埋め込まない。`EXPO_PUBLIC_*` は公開値として扱う |
| NFR-05 | 障害表示 | 通信失敗、HTTPエラー、入力不備を画面へ通知。サーバーエラーを成功に変換しない |
| NFR-06 | 時刻 | APIへはタイムゾーンオフセットなしのローカル日時文字列を送る（運用上の時区間仕様と要整合） |
| NFR-07 | テスト | `node --test` によるロジック・モックテストと`tsc --noEmit`をCIで実行 |
| NFR-08 | 決済 | HTTPSかつ許可リスト内ホストへの遷移。戻り操作を成功と誤認しない |

- バックエンド内部での予約の所有者認可、決済Webhook処理、レビュー投稿制約の完全性
- 本番のネットワーク障害、日付境界、タイムゾーン取り扱いの結合検証
